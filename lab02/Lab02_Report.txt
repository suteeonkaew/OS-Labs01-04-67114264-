2. System Observation (htop)

During multithreading, the CPU-bound Python threads shared one interpreter and one GIL. htop therefore showed roughly one core's worth of sustained CPU work, although the OS could move threads between cores. During multiprocessing, each process had a separate interpreter and GIL, so the OS scheduled them across multiple cores. Several or all CPU bars became busy at the same time.

3. Analysis: The GIL

Multithreading did not make this CPU-bound loop faster because CPython's Global Interpreter Lock allows only one thread at a time to execute Python bytecode in a process. Thread creation, context switching, and lock coordination may even add overhead. Multiprocessing is more suitable because each process has its own interpreter and GIL, allowing true parallel execution on different CPU cores. Its trade-offs are higher memory use and process-management or communication overhead.
